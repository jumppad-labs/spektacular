All success metrics are covered by automated behavioural tests; no manual test plan is required.

Spec 000036 explicitly defines no Success Metrics section (per plan.md's `## Testing Approach`: "Spec 000036 defines no Success Metrics — there is nothing to carry into a metric→verification mapping"). The spec's Acceptance Criteria served as the verification targets instead, and all of them are covered by the automated test suite added across this plan's four phases (`managed_section_test.go`, `draft_presentation_test.go`, and the extended `TestInstallSpecTriggerSection_CrossAgentIdempotency`).

One deliberate, pre-existing gap noted in the plan's Testing Approach and Out of Scope sections: no automated or manual test verifies an LLM's actual runtime behavior change (i.e. that a live agent session literally stops using dialog UI for drafts after reading the installed instruction). This is not mechanically testable from this repository and is explicitly out of scope, matching the existing test suite's own scope for the other two managed sections (which likewise only verify that the correct Markdown is installed to `AGENTS.md`, not that an agent's downstream behavior changes).
